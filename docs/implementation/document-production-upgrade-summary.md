# Document Production Upgrade Summary

## Architecture

The upgrade adds `src/lib/document-production` as a shared document layer for report engine exports, annual accounts, trustee packs, filing packs, Gift Aid schedules, audit logs, fund summaries, payroll reports, bank reconciliation certificates, and evidence indexes.

The existing report loaders and `report_versions` remain the source of truth. Document production converts those sources into a common `DocumentModel`, renders the requested format, stores the file privately, and records an `export_versions` row.

## Database And Storage Security

Migration `20260501090000_document_production_exports.sql` adds:

- private `document-exports` bucket
- `export_versions`
- workspace-scoped RLS
- storage policies using the first folder path segment as `workspace_id`

Admin and treasurer roles can manage export versions. Members can only read approved/final exports where the source allows member visibility.

## Template System

The template registry includes:

- Report cover
- Report contents
- Statement page
- Notes page
- Appendix page
- Signature/approval page
- Evidence index
- Export footer

Every document receives organisation name, charity number, period, title, generated date, generated by, version, status, footer text, and confidentiality text.

## Export Formats

PDF uses `@react-pdf/renderer` with A4 layout, footer, metadata, draft watermark, sections, tables, and approval/signature support.

DOCX uses a generated OpenXML package suitable for editable narrative, headings, tables, and trustee/examiner comments.

Excel uses `exceljs` with summary tabs, schedule tabs, frozen headers, widths, basic number formats, and formula support.

CSV reuses the existing CSV escaping utility for schedules and raw data exports.

## Versioning And Downloads

`export_versions` stores file path, checksum, generated user, generated date, status, format, source report id, source kind, validation snapshot, and metadata. Files are uploaded to private storage and downloaded through `/api/document-exports/[exportVersionId]`, which verifies the active organisation and export visibility before returning a short-lived signed URL.

## Integrations

- `src/lib/reports/engine/service.ts` routes non-CSV report exports through stored document production.
- `src/lib/reports/engine/exports.ts` documents the document-production renderer for non-CSV snapshots.
- `src/lib/annual-accounts/exports.ts` exposes document-production rendering for annual accounts.
- `src/lib/reports/trustee-packs/exports.ts` exposes document-production rendering for trustee packs.
- `src/lib/year-end-close/filing-pack.ts` now describes generated document references rather than placeholder hooks.
- `src/app/(app)/reports/export-pack/page.tsx` can resolve report/format links to generated export downloads.

## Remaining Limitations

- The Word renderer creates a valid minimal OpenXML document; richer comment metadata and advanced styles can be layered later.
- Chart rendering prioritises readable tables and summary panels before image-based chart capture.
- Existing legacy CSV client downloads remain in place for working papers.
- Supabase migration push is intentionally not performed until explicitly requested.
